# Tool Release-Readiness Checklist

Use this checklist before publishing or substantially revising any tool page.

## A) Problem and scope clarity
- [ ] Problem statement describes a concrete user workflow pain point.
- [ ] Tool role in the broader tools collection is explicit.
- [ ] MVP scope is bounded (in-scope and out-of-scope items listed).
- [ ] Current status is clearly described and realistic.

## B) Technical credibility
- [ ] Inputs, outputs, and core transformations are explicitly described.
- [ ] Hard dependencies (schemas, adapters, identity models, storage) are listed.
- [ ] Failure modes and edge conditions are acknowledged with fallback behavior.
- [ ] Any claimed integration has a linked evidence page or implementation note.

## C) Non-hype quality gate
- [ ] Claims are measurable and non-speculative.
- [ ] No "autonomous" or "intelligent" claims without concrete behavior description.
- [ ] Limits and known gaps are visible.
- [ ] Next milestone is testable with a pass/fail condition.

## D) Practical usability signal
- [ ] At least one end-to-end usage scenario is included.
- [ ] Reader can identify first action to try the tool concept.
- [ ] If coordination with other tools is required, sequence is documented.
- [ ] Privacy/consent expectations are stated when handling personal or communication data.

## E) Publication hygiene
- [ ] Top/bottom related-page cross-links are present.
- [ ] Terminology is consistent with the collection and architecture pages.
- [ ] Page avoids speculative diagrams and placeholder graphics.
- [ ] Sensitive implementation details, credentials, or private endpoints are excluded.
